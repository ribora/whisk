# whisk

Compile-time codegen for input binding **and** validation. Reads struct tags,
emits straight-line Go — `Parse(src scan.Source) error` to populate a struct
from a source, and `Validate() error` to check it. No runtime reflection; the
generated code is plain Go with direct field access.

The source is an interface, not a transport. An HTTP request, an AMQP delivery
and a byte slice all satisfy it, and the adapter decides what a scope like
`query` or `routing-key` means — whisk emits the lookup verbatim and hardcodes
nothing.

Binding and validation are independent plugins behind one orchestrator, so a
struct can use either, both, or neither — a single `//go:generate` directive
runs the lot.

## Install

```bash
go install github.com/ribora/whisk/cmd/whisk@latest
```

## Quick start

```go
//go:generate whisk $GOFILE
package model

type LoginRequest struct {
    UserID   string   `scan:"path=userId"            validate:"required"`
    Token    string   `scan:"header=Authorization"   validate:"required,min=8"`
    Email    string   `json:"email"                  validate:"required,email"`
    Password string   `json:"password"               validate:"required,min=8,max=64"`
    Tags     []string `scan:"query=tag,repeated"     validate:"unique,dive,required"`
}
```

`go generate` runs whisk with `$GOFILE` set to the source file — only that
file is processed. Output lands in `login_whisk_gen.go` next to it, tagged
`//go:build !whisk` and headed `// Code generated by whisk. DO NOT EDIT.`

The generated file provides:

```go
func (s *LoginRequest) Parse(src scan.Source) error // bind from request
func (s *LoginRequest) Validate() error             // check (only if it has validation)
```

Wire it through `github.com/ribora/http/server`:

```go
import "github.com/ribora/http/server"

// Handler style — Parse + Validate run before fn; first error short-circuits.
mux.Post("/login", server.Bind(func(ctx context.Context, req *model.LoginRequest) (*server.Response[Out], error) {
    // req is populated and validated
    ...
}))

// Or bind manually inside a raw handler:
req, err := scan.Into[model.LoginRequest](server.From(r))
if err != nil { return err }
```

Any other source binds the same way — `scan.Into[T](src)` over an `amqp.Source`
in a queue consumer, or over `scan.FromBytes(b)` for a file or a test fixture.

## Why not an existing library

The field is crowded, and most of it is a better fit than whisk for some job.

**`huma`** is the closest neighbour: code-first, derives OpenAPI from Go types,
validates requests. It does that at run time through reflection, is HTTP-only,
and owns the handler signature and router integration. If you want one package
to hold routing, docs and validation together, and reflection on the request
path is fine, huma is less machinery than assembling this yourself.

**`go-playground/validator`** is validation only, at run time, by reflection.
whisk's tag syntax is a deliberate subset of it, so rules port directly — it is
the dialect this borrows, not a competitor. Reach for it when you want no
codegen step and no binding.

**`ogen` and `oapi-codegen`** run the other direction: an OpenAPI document is
the source of truth, and types, routing, decoding and schema-derived validation
are generated from it. If your spec is written first and reviewed by people who
do not read Go, that is the correct arrangement and whisk is the wrong tool.

**`ShouldBind` in gin / echo / fiber** binds by reflection from a type tied to
the HTTP request, with validation as a separate step.

Two axes sort these apart — where the truth lives, and when the work happens:

|  | at run time | at generate time |
|---|---|---|
| **spec-first** | — | `ogen`, `oapi-codegen` |
| **code-first** | `huma`, `go-playground/validator`, `ShouldBind` | **whisk** |

The generated half gets a misspelled tag as a build failure rather than a
run-time panic or a silently skipped check, and leaves straight-line Go in the
repository — so "what happens to this field" is answered by reading a file, not
a library's internals. The code-first half keeps Go as the source of truth.

**And one thing none of them do: the source is an interface, not a transport.**
`Parse` takes a `scan.Source`, and the scope in a tag is an opaque string the
adapter interprets. One struct binds from an HTTP request, an AMQP delivery, or
`scan.FromBytes(b)` in a test, with no separate decoding layer per transport.

Neither is free: you own a `go generate` step, generated files in the tree, and
one more tag dialect whose agreement with `go-playground/validator` is checked
by these tests rather than by upstream's.

## Binding tags — `scan:`

Body is unmarshalled (JSON by default) when some field has no `scan:` tag, and
it writes only fields without a tag or with `scan:"-"`. A scoped or embed field
never comes from the body: a request without `X-User-Id` cannot supply the
caller as `{"userid":"…"}`. Order is: body → embed delegates → scoped lookups →
`parse()` hook.

The exception is a struct that decodes itself — `UnmarshalJSON` for `json`,
`Unmarshal<FORMAT>` in general, own or promoted: the body goes to it whole, and
keeping it off scoped fields is that method's job.

| Tag | Effect |
|---|---|
| `scan:"<scope>=<key>"` | `src.Lookup("<scope>", "<key>")` into the field |
| `scan:"<scope>=<key>,repeated"` | `src.LookupAll(...)` for a `[]T` field |
| `scan:"embed"` | delegate to a **named** struct field's `Parse` |
| `scan:"-"` | skip whisk binding for this field |
| *(no scan tag)* | field comes from the body unmarshal |

`<scope>` is an **opaque string** — the `Source` adapter decides what it means.
The HTTP adapter (`github.com/ribora/http/server`) defines
`path`/`query`/`header`/`cookie`/`form`; an AMQP or Kafka adapter can define
its own (`routing-key`, `topic`, …). whisk emits the lookup verbatim and never
hardcodes a scope.

```go
type ListUsers struct {
    Status string   `scan:"query=status"`          // ?status=active
    Tags   []string `scan:"query=tags"`            // ?tags=a,b,c  (CSV: split, trim, skip empty)
    Roles  []int    `scan:"query=roles,repeated"`  // ?roles=1&roles=2 → LookupAll
}
```

`scan:"-"` skips only whisk's scoped binding. To exclude a field from the body
too, add the stdlib `json:"-"` / `xml:"-"`.

### Type conversions

| Field type | Conversion |
|---|---|
| `string` | direct |
| `int*`, `uint*`, `float*` | `strconv.Parse*` |
| `bool` | `strconv.ParseBool` |
| a named type over any of the above | same call, then a conversion — `type Page int` lands as `Page(parsed)` |
| a type declaring `UnmarshalText([]byte) error` | the raw value is handed to it — `uuid.UUID`, `time.Time`, your own ids |
| `[]T` where T is one of the above | per-element |
| anything else | `// TODO whisk:` marker — handle in the `parse(src)` hook |

For basic kinds the call is picked by the **underlying** kind and the conversion
names the declared type, so `type Status string` and `[]Status` bind without a
hook. The width comes from that kind too, so `type Small int8` refuses `300`
exactly as a plain `int8` does rather than wrapping it to `44`; `int` and `uint`
are parsed at the platform width.

`encoding.TextUnmarshaler` **wins over that**: a type that declares a text
decoder means to be built through it, and converting around it would silently
drop whatever it normalises. Pointer fields are allocated before the call, so
`*uuid.UUID` stays nil when the parameter is absent. The decoder's error is
wrapped as `scan.ErrPayload` with the field name, like a `strconv` failure.

`json.Unmarshaler` is deliberately **not** consulted for scoped values: a query
parameter is a bare string, not a JSON document, so a type implementing only
`UnmarshalJSON` would need `?id="abc"` to work and fail on `?id=abc`. In the
**body** those types bind normally — `json.Unmarshal` honours both interfaces
there.

> **Migrating a field to a decoding type changes the class of the error.** whisk
> returns kinds, not statuses: a bad value in `ID string` with `validate:"uuid"`
> is a `*validate.ValidationError`, while the same value in `ID uuid.UUID` fails
> in `Parse` and comes back wrapped in `scan.ErrPayload`. What that becomes is up
> to whoever renders it — the HTTP middleware in `ribora/http` answers the first
> with **422** and `type: validation_failed`, the second with **400**; a queue
> consumer over the same struct has no status to answer with at all. Both classes
> are defensible, but the switch is silent, so change the renderer's contract
> alongside the field, or keep the string.

Conversion failures wrap `scan.ErrPayload` with the field name.

### Mixins — `scan:"embed"`

`scan:"embed"` marks a **named struct field** whose type has its own `Parse`,
and the generated parent `Parse` delegates to it (`s.Field.Parse(src)`) instead
of duplicating the field-by-field logic. The field must be a **value**: a
pointer embed is a codegen error, since allocating it used to depend on the
parent's body unmarshal and broke once the body became conditional. Allocate
explicitly in a `parse(src)` hook if you need one.

```go
type Pagination struct {
    Page    int `scan:"query=page"`
    PerPage int `scan:"query=per_page"`
}

type ListRequest struct {
    Page   Pagination `scan:"embed"`   // named field, not an anonymous embed
    Status string     `scan:"query=status"`
}
```

The field type's `Parse` must exist — generate it in the same run (same file),
or ensure its package has its own whisk target. A missing method is a normal
Go compile error in the generated file. `scan:"embed"` needs a single struct to
delegate to, so an inline anonymous struct or a slice/map field is a codegen
error — reach for a `parse(src)` hook there.

**Use a named field, not Go embedding.** Anonymous embedding (`Pagination`
without a field name) also works, but the embedded type's generated `Parse`
is *promoted* into the parent's method set — leaking a binding method where
callers don't expect it, and letting a non-generated parent silently resolve
`Parse` to the partial embedded one. whisk emits a **warning** for this and
keeps going; prefer a named field to keep delegation explicit.

**A mixin with body fields is read flat, and that costs a pass.** The parent's
decode leaves the embed out, so a body key such as `"page"` or `"user"` is never
matched against the embed field's name. The mixin's own `Parse` reads its
fields, decoding the same body again. So a parent with body fields and *n*
body-carrying mixins decodes the body *n+1* times, each pass filling a disjoint
set of fields. Not redundant work, but not free either; the way out would be
anonymous embedding, which leaks `Parse` into the parent's method set.

**A format name on the embed field is a codegen error.** `scan:"embed"` says the
inner fields come flat from the same body; `json:"page"` asks for a nested
object, which the parent never decodes. Drop the name. The tag checked is
whichever `-format` names, so `-format=xml` checks `xml` and ignores `json`.

**Bordering check:** if a field's type carries `scan:` tags but the field
isn't marked `scan:"embed"` (or `scan:"-"`), whisk **errors** at codegen —
those tags would silently never populate when the parent decodes from body.
This also catches a broken delegation chain (e.g. an `embed` whose target
reaches a scan-tagged struct through a non-`embed` field).

### Custom binding hook — `parse(src)`

Define `func (s *T) parse(src scan.Source) error` and whisk calls it last,
after the generated body. Use it for non-scalar conversions, derived fields,
or defaults.

```go
func (s *ListUsers) parse(src scan.Source) error {
    if s.Page < 1 { s.Page = 1 }
    return nil
}
```

A struct with only a `parse` hook and no `scan:` tags still gets a generated
`Parse` (body unmarshal + the hook call).

## Validation tags — `validate:`

Tag syntax is a deliberate subset of `go-playground/validator`, so rules port
directly. Errors are collected (not first-fail) and returned via
`errors.Join`. On a field, a failed `required` short-circuits the field's
other checks (no spurious "email" error on an empty string).

### Structural

| tag | applies to | notes |
|---|---|---|
| `required` | any | string `!= ""`, number `!= 0`, slice/map non-empty, pointer non-nil, `time.Time` non-zero (not valid on `bool` — use `equal`) |
| `min`, `max`, `gt`, `gte`, `lt`, `lte` | string, number, slice/map, `time.Time` | length for strings/slices/maps, value for numbers, point-in-time for `time.Time` (`now`, `7d`, `-30d`, `2024-01-01`) |
| `eq`, `ne`, `equal`, `neq` | string, number, bool | value comparison (a codegen error on `time.Time` — bound an instant with `gte`/`lte`) |
| `len` | string, slice/map | exact length |
| `oneof=A B C` | string, number | space-separated whitelist |

Every tag other than `required` sits inside a presence guard, so an empty
optional field says nothing and only `required` reports absence:

```go
Id  string `validate:"required,uuid"`  // empty  -> required fails
Alt string `validate:"uuid"`           // empty  -> silent, it is optional
```

A named type is classified by what it is declared over: `type ID string` is a
string for the guard, for `required` and for the `Kind` the error carries, and
it is converted on the way into the built-ins.

An element of a collection follows the same rule, so `dive,min=2` lets an empty
string through and `dive,required,min=2` is how you refuse one — and an empty
element then reports `required` alone rather than `required` and `min` together.

### Format

`email`, `uuid`, `url`, `datetime=<layout>`, `charset=alpha|alphanum|numeric|hex`,
`lowercase`, `uppercase`, `contains=X`, `startswith=X`, `endswith=X`,
`ip` (`ip=v4`/`ip=v6`), `cidr`, `hostname`, `fqdn`, `mac`, `base64`, `json`,
`phone`, `semver`, `timezone`, `duration`, `hexcolor`, `currency`, `country`,
`locale`.

This is what whisk brings. What a tag may say in a *particular* project is that
plus whatever its storage directory holds, and `whisk tags` prints the two
together — see [whisk tags](#whisk-tags).

### Collections

| tag | notes |
|---|---|
| `dive` | recurse into slice elements / map values |
| `unique` | duplicate check on a slice of comparable elements |
| `unique=Field` | duplicate check on a slice of structs, keyed by `v.Field` |

`dive` chains for nesting: `[][]T` → `dive,dive,X`; `map[K][]V` → `dive,dive,X`.

**Auto-dive:** a struct-typed field with no explicit `dive` gets one added
automatically, so nested `Validate()` is invoked without ceremony:

```go
type Order struct {
    Customer Customer   // Customer.Validate() called automatically
    Items    []LineItem // each LineItem.Validate() called, index in the error path
}
```

This chains transitively: if `Customer` itself has no validate tags but
contains a field whose type does, every level still gets a `Validate()` and is
dived into. A nested type whose graph carries no validation at all gets no
`Validate()` and isn't dived into (no empty-method bloat). Dives into a type
known at codegen to have a `Validate` are emitted as direct calls; interface-
typed fields fall back to a runtime type assertion.

### Cross-field logic — `validate()` hook

Anything needing another field, business state, or a registry goes into a
`func (s T) validate() error` method (lowercase). It runs after the generated
checks; its errors merge into the same `errors.Join` chain. Tags stay a
per-field structural language — no `required_if`/`eqfield` sub-DSL.

```go
func (o Order) validate() error {
    if o.Status == "cancelled" && o.CancelledAt.IsZero() {
        return &validate.ValidationError{
            Segments: validate.Path{validate.NewFieldSegment("go", "CancelledAt")},
            Tag:      "required_when_cancelled",
        }
    }
    return nil
}
```

### Custom validators

Export `Is<PascalTag>` from any file in the storage directory (default
`pkg/validate` at the module root) — the lookup is by func name, so the file can
be called whatever suits the package:

```go
// pkg/validate/rules.go
package validate

func IsPasscode(value string, args ...string) bool {
    return len(value) == 6
}
```

`validate:"passcode"` then resolves to a call into that package (imported under
the alias `checks`). Signatures:

- `func IsTag(value T, args ...string) bool`
- `func IsTag(value T, args ...string) (bool, error)` — the error is stashed
  into `ValidationError.Err` for the consumer to unwrap

A custom validator whose name collides with a built-in **wins** — that's how you
override a default without forking whisk. Since that's the one case where the
model's reader can't tell which check runs, whisk says so:

```
whisk: warning: checks.IsEmail overrides the built-in "email" validator
```

The storage dir is set with `-validate.storage` or `validate.storage` in
[whisk.yaml](#whiskyaml). A nonexistent dir simply means no custom validators —
nothing was promised, so nothing is reported. A tag that resolves to neither a
built-in nor a validator **is** a codegen error, and it names where it looked:

```
whisk: plugin validate: Auth.Code: unknown validator tag "passcode": not a
built-in, and no func IsPasscode in pkg/validate (found there: IsPassCode);
point -validate.storage or whisk.yaml's validate.storage at the right directory
```

A file in the storage dir that doesn't parse is an error too, rather than a
silent miss that reports every tag in the project as unknown.

## Errors

```go
type ValidationError struct {
    Segments Path   // structured path to the field
    Tag      string // the tag that failed ("min")
    Value    string // tag argument or sub-field name ("8")
    Kind     string // KindStr | KindValue | KindSlice | KindObj | KindTime
    Err      error  // optional underlying detail (from error-returning validators)
}
```

`Kind` says what shape of value failed, so a client can word `min` as "too
short" for a string and "too few items" for a list. Compare it against the
`Kind*` constants — the generated code emits those, not literals.

Paths are structured (`[]PathSegment`), not strings — the caller renders them
in whatever style the receiver expects:

```go
p := ve.Segments
p.Format(validate.GoFormatter)   // Order.Items[0].Name
p.Format(validate.JSONFormatter) // order.items[0].name  (falls back to Go names)
```

Each field segment carries the Go name plus tag names selected by `-format`
(JSON ⇒ `json` names, XML ⇒ `xml` names). A scoped field without that tag is
named by its key — `scan:"query=startedAt"` renders as `startedAt` — and an
embed adds no segment, since its fields arrive flat. Walk the joined error with
the standard `Unwrap() []error`:

```go
if me, ok := err.(interface{ Unwrap() []error }); ok {
    for _, e := range me.Unwrap() {
        var ve *validate.ValidationError
        if errors.As(e, &ve) { /* handle ve */ }
    }
}
```

The `github.com/ribora/http/server/middleware` error renderer does this for you,
turning validation errors into a `422` with a JSON path/tag/value/kind list and
`scan.ErrPayload` into a `400`.

## Custom body format

`json` and `xml` are built in. Any other `-format` name must be backed by a
**custom extractor** — a Go function that decodes the body. Declare
`func Unmarshal<PascalFormat>(b []byte, v any) error` in any file of the
extractor directory (default `pkg/scan` at the module root):

```go
// pkg/scan/formats.go
package scan

import "github.com/BurntSushi/toml"

func UnmarshalToml(b []byte, v any) error { return toml.Unmarshal(b, v) }
```

Then `whisk -format=toml $GOFILE`:

```go
func (s *Doc) Parse(src scan.Source) error {
    if body := src.Body(); len(body) > 0 {
        if err := bodyfmt.UnmarshalToml(body, s); err != nil { // your extractor, imported aliased
            return failure.Wrap("%w: %w", scan.ErrPayload, err)
        }
    }
    ...
}
```

The signature `(b []byte, v any) error` is the universal decoder shape, so most
libraries (`toml`, `yaml`, `msgpack`, …) plug in with a one-line wrapper. The
format name also becomes the struct-tag whisk reads for path segments — so a
`toml` format pairs with `toml:"..."` field tags and `toml`-named error paths.
A `-format` that's neither built in nor found in the extractor dir is an error
naming the directory it searched.

`-format` takes one name. A model is parsed from one body format, and that same
name picks the tag whose field names appear in error paths.

This mirrors custom validators: convention directory, name-based lookup, no
flags describing the function inline.

## CLI

```
whisk [-format NAME] [-scan.extractor DIR] [-validate.storage DIR] [FILE]
whisk init
whisk tags

  -format            body format: json | xml | <custom>  (default json)
  -scan.extractor    dir of custom body-format extractors (Unmarshal<Format>),
                     relative to the project root         (default pkg/scan)
  -validate.storage  dir of user-defined Is<Tag> validators,
                     relative to the project root         (default pkg/validate)

  FILE               target source file; defaults to $GOFILE
  init               write whisk.yaml at the module root
  tags               print what a validate tag and -format may say here
```

### whisk tags

Writing a tag that does not exist is already a generation error naming the tag,
the line and the directory searched. The reverse is not caught, and it is the
common mistake: a check whisk or the project already has, written again by hand
in a handler because nobody knew it was there.

`whisk tags` answers that, and it is the only thing that can. The built-ins are
whisk's, the custom ones are the project's, and *which* directory is the
project's follows **flag > whisk.yaml > default** — so no document can list them
and reading the source means resolving that chain first. The listing groups them
by where the check comes from, names the `Is<Tag>` behind each one, says which
of the three sources decided the directory, and marks two things that would
otherwise mislead:

- a custom check **shadowing** a built-in of the same name, listed once, under
  the custom entry that actually answers it;
- a function **no tag can reach** — `Ispasscode` where `IsPasscode` was meant.
  The generator would not find it either, so a directory it sits in looks wired
  and is not.

It reads no source file and resolves the project from the working directory,
which means it cannot see a `-validate.storage` passed on one `//go:generate`
line. The report says so. To ask about that directory, pass the flag — **before**
the subcommand, since Go's flag parsing stops at the first operand:

```
whisk -validate.storage=internal/checks tags
```

Flags follow a two-tier rule:

> A flag is **top-level** iff more than one plugin reads it; otherwise it lives
> under `-<plugin>.<flag>`.

- `-format` is top-level — scan uses it to pick the body decoder, validate uses
  it to pick the path-segment tag names. Two consumers ⇒ no single namespace
  owns it.
- `-scan.extractor` / `-validate.storage` are each read by one plugin.

Path-segment tags are **not** a flag — they're derived from `-format`.

```go
//go:generate whisk $GOFILE                          // json body
//go:generate whisk -format=xml $GOFILE              // xml body, xml error paths
//go:generate whisk -format=toml $GOFILE             // custom extractor in pkg/scan
//go:generate whisk -validate.storage=internal/checks $GOFILE
```

## whisk.yaml

Project-wide settings live in `whisk.yaml` at the module root, so the paths are
stated once and reviewed like any other file instead of being repeated on every
`go:generate` line. `whisk init` writes it:

```yaml
# whisk.yaml — project settings for the whisk generator.
# These are whisk's defaults, written out so the paths are visible. Drop a line
# to follow the default instead; a flag on a go:generate line overrides both.

format: json             # json | xml | <custom, see scan.extractor>

scan:
  extractor: pkg/scan    # dir holding func Unmarshal<Format>([]byte, any) error

validate:
  storage: pkg/validate  # dir holding func Is<Tag>(value, args ...string) bool
```

Each section is the plugin's own, matching its flag namespace: `-scan.extractor`
is `scan.extractor` here. Precedence is **flag > whisk.yaml > default** — a value
from the file applies only where the invocation didn't pass the flag, so a
per-file override on a `go:generate` line keeps working.

- **No file is a normal project.** Missing `whisk.yaml` is identical to
  all-defaults, silently: nothing was promised, so there is nothing to warn
  about. Requiring the file would tax every project that uses no custom
  validators — most of them.
- **An unknown key is an error**, at the top level or in a section. A typo can
  never be intended, and a config that silently means something else is worse
  than no config.
- **`whisk init` never overwrites.** A second run reports the file it left alone.
- A written value **pins** that setting; dropping the line follows whisk's
  default.

## Generated code shape

```go
//go:build !whisk

// Code generated by whisk. DO NOT EDIT.

package auth

import (
    "encoding/json"
    "errors"

    "github.com/ribora/failure"
    "github.com/ribora/whisk/scan"
    "github.com/ribora/whisk/validate"
)

func (s *LoginRequest) Parse(src scan.Source) error {
    if body := src.Body(); len(body) > 0 {
        payload := struct {
            Email    string `json:"email"                  validate:"required,email"`
            Password string `json:"password"               validate:"required,min=8,max=64"`
        }{
            Email:    s.Email,
            Password: s.Password,
        }
        if err := json.Unmarshal(body, &payload); err != nil {
            return failure.Wrap("%w: %w", scan.ErrPayload, err)
        }
        s.Email = payload.Email
        s.Password = payload.Password
    }
    if v := src.Lookup("path", "userId"); v != "" {
        s.UserID = v
    }
    // … Token, Tags
    return nil
}

func (s *LoginRequest) Validate() error {
    var errs []error
    if s.UserID == "" {
        errs = append(errs, &validate.ValidationError{
            Segments: validate.Path{validate.NewFieldSegment("go", "UserID", "json", "userId")},
            Tag:      "required",
            Kind:     validate.KindStr,
        })
    }
    return errors.Join(errs...)
}
```

The `//go:build !whisk` tag means whisk's own loader (which runs with
`-tags whisk`) never sees stale generated code — so renaming a field can't
break the type-check on the next run. The orchestrator also deletes the old
`*_whisk_gen.go` before loading, belt-and-suspenders.

## How it works

whisk loads the target package with `golang.org/x/tools/go/packages` (full type
info, one load per file), then runs each plugin against the parsed structs.
A plugin emits a code section + the imports it needs; the orchestrator merges
sections, dedupes/sorts imports, runs `go/format`, and writes only if the
output changed.

```
github.com/ribora/whisk/
├── scan/                  runtime: Source interface, ErrPayload
├── validate/             runtime: validators, ValidationError, Path, formatters
├── cmd/whisk/            CLI entry point
└── internal/
    ├── shared/           loader + StructInfo/FieldInfo (tag-agnostic)
    ├── generator/        Plugin interface, orchestrator, file render
    └── plugins/
        ├── scan/         Parse() codegen
        └── validate/     Validate() codegen
```

Adding a third plugin (e.g. swagger) means implementing the `Plugin` interface
and, if it has CLI settings, a `Config`/`BindFlags` registered under its name —
the orchestrator and `main` don't grow special-case knowledge.

## Contributing

The generator is covered by golden files: each case under `testdata/cases/<name>/`
is a pair of `setup.go` (input) and `golden_whisk_gen.go` (expected output). The
suite lives in `cmd/whisk/goldens_test.go` rather than beside the cases, because
the go tool ignores `testdata` in wildcard patterns — from in there, `go test ./...`
ran none of it and the goldens drifted unnoticed.

Three tests, and the second two exist because the first is not enough:

- `TestSuccess` compares bytes;
- `TestGoldensCompile` builds every case, since a wrong import list passes a byte
  comparison and still emits a file that does not compile;
- `TestGoldensRun` executes the cases listed in `runnableCases`, since a missing
  nil guard compiles and only fails when something calls it.

To add a case:

1. write `testdata/cases/<name>/setup.go`;
2. add it to `successCases` (or `errorCases` with an expected error substring) in
   `cmd/whisk/goldens_test.go`, and to `runnableCases` if it carries a `_test.go`;
3. `make golden` to populate the golden, then read it;
4. `make test` to check that it compares, compiles and runs.

## Limitations

Intentional, not pending TODOs:

- **Only json and xml are built in.** Other formats need a custom extractor
  (see "Custom body format").
- **No cross-field / map-key validation tags.** Use the `validate()` hook.
- **Map iteration order is non-deterministic** — errors on map values appear in
  random order; sort by path if order matters.
- **`unique=Field`** takes a single direct field name; composite keys go in
  `validate()`.
- **Scoped fields that are neither a basic kind nor a `TextUnmarshaler`** emit a
  `// TODO whisk:` marker — convert them in a `parse(src)` hook. A struct with
  no text decoder is the usual case.
- **`[]*T` from a scope** is not bound even when `*T` decodes text; use a value
  slice, or the hook.
